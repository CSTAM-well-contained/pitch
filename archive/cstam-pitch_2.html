03 Architecture

The control plane decides. The gateways carry traffic.

CSTAM × FelCloud · The Resilient IP Optimizer

Left, the control path. Our control plane, cpd, written in Go, with PostgreSQL as the single source of truth. It allocates IPs, creates the VM on OpenStack through Nova and Neutron, and publishes routes to the gateways.

Right, the data path. Visitors hit one public floating IP, mapped to a virtual IP held by whichever gateway is MASTER. Each gateway runs HAProxy, keepalived and our agent, gwagent.

The key design choice: cpd decides, but never carries traffic. If cpd stops, the gateways keep routing from their last saved state.

04 IPAM & team lifecycle

No IP is ever given twice, and none is reused too early.

1,000 parallel allocations on 128 slots → 128 leases, 872 clean "pool full", 0 duplicates

50 IPs back in the pool 63 s after a hackathon ends, and reused by the next one

Short leases: on expiry, route removed at that second and sandbox deleted 1 s later

CSTAM × FelCloud · The Resilient IP Optimizer

IP management is where conflicts used to happen.

A registration inserts the team and leases its IP and routing slot in the same transaction, under a PostgreSQL advisory lock. Two concurrent requests can never get the same IP. We tested a thousand parallel allocations: zero duplicates.

On teardown, the route is removed first and the IP goes to quarantine. It only comes back when every live gateway has acknowledged a newer route table, 60 seconds have passed, and OpenStack confirms no port holds it. So a recycled IP can never receive the previous team's traffic.

The gateways. First: adding a team doesn't even reload HAProxy. We pre-declare 128 backends and swap the host map through the runtime API, so the route is live in 24 milliseconds.

Config changes go through a pipeline: validate, swap atomically, hitless reload, verify through the real frontend, and roll back on any failure, in 139 ms. We apply on the backup first, so the master never gets a config its peer refused. Zero dropped requests over 96 thousand.

Failover is VRRP with half-second heartbeats, gated on health, with nopreempt: 0.3 seconds planned, under 2 seconds on a real crash.

S6 Design decisions

Why it is built this way.

Our IPAM, not Neutron's

Neutron would free an IP the moment the port goes. We need to wait until no gateway can route to it: quarantine plus gateway acks.

PostgreSQL as the truth

Leases, routes and the routes generation change in one transaction. A crash never leaves a route without a lease.

Pre-declared backends

128 slots in haproxy.cfg. Adding a team = runtime API + atomic map swap: no reload, 24 ms.

Whole generations, acked

gwagent long-polls and applies a full route table, never a diff and never an older one. It saves it to disk, so a gateway restarts without cpd.

nopreempt + health gate

A fresh gateway never takes the VIP before it has routes, and a recovered one doesn't cause a second switch.

Same flow, two drivers

OpenStack VM driver on FelCloud, Docker driver locally: same API, controller, IPAM and gateways, so 50-team tests fit the 10-VM quota.
